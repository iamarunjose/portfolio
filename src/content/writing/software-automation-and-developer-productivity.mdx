## 1. Automation That Helps vs. Automation That Hides

The goal of software automation is not to create complex black-box scripts that nobody dares to touch. Good platform automation acts as executable documentation: deterministic, fast to feedback, and transparent when a check fails.

## 2. Principles for High-Leverage Engineering Workflows

- **Fast Local-to-CI Parity**: Every check that runs in a pipeline should be runnable locally with a single command.
- **Idempotent Operations**: Scripts and provisioning steps should produce the exact same state whether run once or ten times.
- **Actionable Failure Diagnostics**: When a build, lint, or infrastructure gate fails, the output should immediately tell the developer *why* and *how to fix it*.

```bash
# Principle: Single-command deterministic verification
npm run check   # Validates types, build integrity, routes, and accessibility rules
```
